# Shared package (`com.adrian.shared`)

Reusable Unity code shared across my projects. Lives in its own repo (github.com/Plapi/shared) and is added to each project as a git submodule at `Packages/com.adrian.shared` (embedded package).

## Module rules

- One folder per module: `Runtime/<Module>/`, namespace `com.Plapamaru.Shared.<Module>`.
- Core assembly `Shared` (`Runtime/Shared.asmdef`) has **no** third-party or optional-package references. Anything needing UniTask, Newtonsoft, DOTween, uGUI or the Input System gets its own small asmdef (e.g. `Shared.UniTask`) inside its module folder.
- Editor-only code goes under `Editor/<Module>/` (assembly `Shared.Editor`) and uses the module's namespace — never a `...Shared.Editor` namespace, it would shadow `UnityEditor.Editor`. Editor-only members of runtime components stay in the runtime file under `#if UNITY_EDITOR` so game code can still call them.
- Commit the `.meta` files Unity generates; projects rely on their GUIDs.
- Components that old projects have on scenes/prefabs: reuse the old script GUID in the new `.meta` (check `grep guid <old>.cs.meta`) and keep renamed fields readable with `[FormerlySerializedAs("oldName")]`, so references and values survive migration.
- Update the module list in `README.md` when adding a module.

## Code style

- Allman braces, 4-space indent, `_camelCase` private fields, file ends with a newline, no BOM.
- No comments or doc summaries unless truly necessary.
- Prefer `IReadOnlyList<T>` / `IList<T>` parameters over concrete arrays/lists.

## Importing a module from an old project

Sources are the sibling repos in the same GitHub folder: `townbuilder/Assets/Plugins` and `lanes/Assets/Plugins`. Where both have a module, townbuilder's copy is newer (namespaced, asmdefs) and is the base.

1. Read both copies; check what other code uses (`grep` usages in both projects) before renaming anything.
2. Port into `Runtime/<Module>/`, change the namespace, clean up, fix obvious bugs, drop what Unity already provides. Renames are fine — old projects migrate when they adopt the package.
3. Verify in the host project with the editor open: `unity recompile .` (no rows = no errors). For logic changes, sanity-check with `unity cmd script eval --file <check.cs>`.
4. Commit inside the submodule (message = module name), then the host project commits the new submodule pointer.

Newtonsoft often arrives as a dependency of other packages (it does in lanes-rush)
- [x] Game states (`Runtime/GameStates/Shared.GameStates.asmdef`, needs UPM UniTask). Replaces townbuilder `Scripts/GameSystem` (`GameSystem`/`GameStateBase`, MonoBehaviour states). States are plain C# objects built with `new` (constructor = per-visit arguments, fresh per visit). Contexts follow townbuilder (`GameState<TContext>`, the context set before the state runs) with improvements: a context is a plain class deriving from the abstract `GameStateBase.Context` (non-generic base, as townbuilder), nested in its state as `public new class Context : GameStateBase.Context`; the caller passes it to `Change`/`Push` (else `new TContext()`), `GameManager.InitContext(Context)` can fill common fields, so states only see the data and actions their context declares, never the manager; state and context types are checked at compile time (no casts). The field is `_context` so the nested `Context` class compiles (same reason `UIView<TData>` uses `Model`). Every state has a context type: `GameState<TContext>` / `GameState<TContext, TResult>`. A pushed child is awaited by its parent instead of cancelling and re-running the parent's `Run`. The machine does not touch UI or input: states call `UIManager` themselves, the game routes Back to `UIManager.HandleBack()` then `Machine.HandleBack()`. Back as a race branch: `WaitForBack(ct)` is completed by the default `OnBack` (townbuilder polled panel flags with `WaitUntil`; await events instead, e.g. UniTask `Button.OnClickAsync`). Dropped from townbuilder: R-to-restart (legacy `Input`), factory saving, `targetFrameRate`, `GameStateUtils` (touch-camera specific)

- [x] Audio (`Runtime/Audio/`, core `Shared` assembly, only engine audio APIs). New, based on lanes `AudioSystem` (game code there): one mixer with groups instead of one mixer asset per channel, a pool of `AudioSource`s instead of a GameObject per sound, volumes by exposed parameter name instead of a `MixerType` enum so each game names its own channels. `AudioMixer.SetFloat` is ignored in `Awake`, so saved volumes are applied in `Start`. `UIButtonSound` (in `Shared.UI`) replaces lanes `UIButtonSound` + its persistent-listener editor tool: it adds a runtime `onClick` listener and holds only an `AudioClip` reference (no settings asset). `UIButtonHaptic` (also `Shared.UI`) does the same with a `HapticFeedback.Type` (Light by default), as lanes did inside `UIButtonSound` on iOS
